Which federated learning algorithm really works on non-IID data?

TL;DR

Four things the data say

Statistical heterogeneity is a central obstacle for federated learning, and many algorithms claim to mitigate it. Published comparisons rarely use equal tuning effort, enough repetitions or statistical tests; here every claim comes with a paired test.

1.75

No universal winner

Friedman test over 47 settings rejects equality, but the Nemenyi critical difference (1.75) only separates FedBN and MOON from the leaders. Only FedAdagrad is significantly better than FedAvg across settings (Holm p = 0.042).

+8.4

Label skew is the hard case

FedAvg falls from 74.5% (IID) to 24.2% for #C = 1. Adaptive server optimizers gain up to +8.4 points on FMNIST #C = 2 — not significant after correction.

17/47

SCAFFOLD is competitive — but costs 2×

With the corrected algorithm it is best-ranked under IID, quantity and feature skew, but it sends two vectors per round: at equal bytes it beats FedAvg in only 17 of 47 settings.

0/47

FedBN does not beat its control

Against the matched BatchNorm control (FedAvg-BN) FedBN is never better and significantly worse in 29 of 47 settings in this global-model evaluation.

Selection guide

Which algorithm to try first?

An uncertainty-aware guide: every recommendation is annotated with its statistical support. These are tendencies of this benchmark (10 clients, 50 rounds, 10 local epochs, small CNN/MLP), not guarantees.

1. What kind of heterogeneity do your clients exhibit?

Pathological label skew

each client holds only 1–2 classes

Moderate label skew

Dirichlet-type, a few classes dominate

Feature / quantity skew, near-IID

mild noise, unbalanced client sizes

In every case

  • Tune the client learning rate for each method (the selected values differ by algorithm and data family).
  • Report at least five seeds and paired tests; treat gaps below ≈2 points as noise.
  • Report communication in bytes, not only in rounds.

Avoid as global-model methods in this regime

  • MOON: never better than FedAvg (0 of 47); clearly worse for #C = 2.
  • FedBN: worse than its FedAvg-BN control in 29 of 47 settings, better in none.

SCAFFOLD against FedAvg: equal rounds vs equal transmitted bytes

Number of settings (out of 47) in which SCAFFOLD has a higher mean accuracy than FedAvg. SCAFFOLD sends a control variate in each direction in addition to the model (2× the payload); at the communication budget FedAvg uses for 50 rounds, SCAFFOLD completes 25.

More local epochs do not pay off in general

MNIST and CIFAR-10, three seeds. From 10 to 30 epochs FedAvg loses 1.25 points on average and FedProx 3.06; only SCAFFOLD (+1.39) and the FedAvg-BN control (+0.47) improve. In every setting some algorithm peaks at 10, another at 20 and another at 30 epochs.

Protocol

How the benchmark is run

Experimental design

  • Federation: 10 clients (4 for FCUBE), full participation, 50 rounds, 10 local epochs, SGD with momentum 0.9, batch 64, weight decay 1e−5.
  • Models: small CNN (images) and 3-hidden-layer MLP (tabular); BatchNorm variants for FedBN and its FedAvg-BN control.
  • Tuning, equal effort: validation data only (10% of the training set), seven representative settings, two tuning seeds disjoint from the evaluation seeds; the search range was extended until no winner lay on its border (1,530 runs).
  • Statistics: 5 seeds (10 for five core settings); paired t-tests with Holm correction; Friedman + Nemenyi; Wilcoxon; 95% confidence intervals.
  • Evaluation: final-round test accuracy; for FedBN the mean over the client models (shared weights + the client's BN state) on the same global test set.
  • Data skews: label (#C = 1, 2, 3; Dirichlet 0.5), feature (Gaussian noise σ = 0.1; FCUBE), quantity (q ~ Dir(0.5)), and IID.

Reproduce

Run it yourself

Everything is deterministic given the seed (GPU kernels are not bitwise deterministic: about ±0.2 points between identical seeds). Runs are resumable and shardable over SLURM jobs, workstations or cloud GPUs; results are one JSON file per run.

# 1. install and test (41 unit / regression tests)
pip install -r requirements.txt
python -m pytest tests -q

# 2. download the datasets once
python -m fedbench.cli.prepare_data --datasets mnist fmnist cifar10 svhn cinic10 fedisic2019 adult fcube
# 3. tune (validation only), select, refine until no winner is on the border of the searched range
python -m fedbench.cli.make_manifest --stage tune --num-shards 36 --out manifests/tune.jsonl
python -m fedbench.cli.run_manifest  --manifest manifests/tune.jsonl --out results --shard 0   # one shard per worker
python -m fedbench.cli.select_hparams --results results/tune --out configs/tuned_hparams.json --table results/tuning_table.csv
python -m fedbench.cli.make_refine --tuned configs/tuned_hparams.json --out manifests/tune_refine.jsonl

# 4. final experiments and the full statistical report
python -m fedbench.cli.make_manifest --stage final --num-shards 36 --out manifests/final.jsonl
python -m fedbench.analysis.make_report --results results --out results/report

SLURM (Narval) and single-GPU / cloud-pod launchers are in scripts/narval and scripts/vm; the runbook is docs/REPRODUCE.md. The data behind every chart on this page is exported by fedbench.analysis.export_site_data.
